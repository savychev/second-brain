# 🧠 Second Brain

**Единая точка захвата мыслей.** Пиши или диктуй мысль одной строкой — система сама
определяет, что это (идея, задача, ссылка или заметка), и складывает в нужное место.
Голова свободна, ничего не теряется.

> 🇬🇧 English version: [README.md](README.md)

> Статус: **Этап 3 — REST API + SQLite** ✅ · Java 21 · Spring Boot 4.1 · SQLite

---

## Зачем это

Мысли, идеи, задачи и ссылки приходят в течение дня и теряются: часть остаётся в голове,
часть — в разрозненных чатах и заметках. Нет единой точки входа, куда можно быстро «сбросить»
мысль, и системы, которая сама разложит её по местам.

**Second Brain** — это «входная воронка»: захват за секунды, автоматическая классификация,
локальная копия для гарантии «ноль потерь». Notion остаётся местом, где заметки лежат и читаются.

## Что уже умеет

- ✅ Принимает мысль любой длины и сохраняет с датой
- ✅ Классифицирует на **IDEA / TASK / LINK / NOTE** по правилам (точность ≥ 80% на тестовом наборе)
- ✅ Извлекает `#теги`
- ✅ Хранит всё в **SQLite** — после перезапуска ничего не пропадает
- ✅ **Отправляет заметки в Notion** — каждый тип в свою базу
- ✅ **Очередь досылки**: Notion недоступен → заметка ждёт и уходит позже сама, по расписанию
- ✅ Три входа: интерактивный REPL, быстрый захват одной командой и **REST API**
- ✅ 139 автотестов, CI на Linux и Windows, корректная работа с кириллицей

## Быстрый старт

Нужна только **Java 21+**. Maven ставить не нужно — в проекте есть wrapper (`mvnw`).

```bash
./mvnw clean package        # Windows: .\mvnw.cmd clean package
```

### Как консольный инструмент

```bash
java -jar target/second-brain.jar
```

```
› надо купить билеты #поездка
  ✓ [TASK] сохранено
    найдено слово-действие: «надо»
    теги: поездка
    → отправлено в Notion
› :stats
  Хранилище: база SQLite …/data/second-brain.db
  Всего заметок: 1
› :quit
```

Команды REPL: `:list [ТИП]`, `:stats`, `:sync`, `:help`, `:quit`.

Быстрый захват одной командой (Windows — через обёртку, чтобы кириллица не портилась):

```powershell
.\sb.ps1 "надо позвонить врачу завтра #здоровье"
```

### Как сервис с REST API

```bash
java -jar target/second-brain.jar --serve
```

Захват мысли по HTTP:

```bash
curl -X POST http://127.0.0.1:8080/notes \
     -H "Content-Type: application/json; charset=utf-8" \
     -d '{"text":"надо забрать посылку #дом"}'
```

```json
{
  "note": { "id": "b30ed3e7…", "type": "TASK", "tags": ["дом"], "synced": true },
  "classification": { "confidence": 0.8, "reason": "найдено слово-действие: «надо»" },
  "notion": { "status": "SENT", "detail": "3aedf8e5…" }
}
```

**Интерактивная документация** — открой <http://127.0.0.1:8080/swagger-ui.html>
и попробуй любую точку входа прямо из браузера.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/notes` | Захват мысли. `201 Created` + заголовок `Location` |
| `GET` | `/notes` | Лента, от новых к старым. `?type=TASK&limit=20&offset=0` |
| `GET` | `/notes/{id}` | Одна заметка |
| `GET` | `/stats` | Счётчики по типам, хранилище, длина очереди |
| `POST` | `/sync` | Ручная досылка очереди в Notion |

> Сервер слушает только `127.0.0.1`. Аутентификации пока нет — см.
> [Известные ограничения](#известные-ограничения).

## Гарантия «ноль потерь»

Вокруг этого свойства построена вся система, поэтому сформулирую точно:

**Заметка сначала записывается в локальное хранилище и только потом отправляется в Notion.**

Следствия видны по всему API:

- `POST /notes` отвечает **`201 Created` даже при недоступном Notion**. Вернуть ошибку было бы
  ложью — заметка **сохранена**, — и подтолкнуло бы клиента отправить повторно, создав дубликат
  страницы. Судьба отправки сообщается отдельно, в блоке `notion`.
- Неотправленные заметки лежат в очереди, определяемой ровно одним признаком:
  `notion_page_id IS NULL`. Она разгребается при следующем запуске, по расписанию пока работает
  сервер, или по требованию через `POST /sync` / `:sync`.
- Фоновая задача и консоль могут работать одновременно, поэтому досылка защищена
  **межпроцессным замком в самой базе**. Без него оба взяли бы из очереди одну заметку
  и создали в Notion две страницы одной мысли.

## Как работает классификация

Этап 1 — прозрачные правила
([`RuleBasedClassifier`](src/main/java/com/secondbrain/classify/RuleBasedClassifier.java)),
приоритет сверху вниз:

1. есть **слово-действие** (`надо`, `купить`, `позвонить`, `todo`…) → **TASK**
2. есть **маркер идеи** (`идея`, `а что если`, `было бы круто`…) → **IDEA**
3. есть **ссылка** (URL или домен) → **LINK**
4. иначе → **NOTE**

Задача намеренно важнее ссылки: «отправить ссылку …» — это задача, а не закладка.

Точность проверяется тестом на наборе из ~30 реальных мыслей
([`RuleBasedClassifierTest`](src/test/java/com/secondbrain/classify/RuleBasedClassifierTest.java)).
Слабые места правил закроет умная классификация через Anthropic API (этап 4) — интерфейс
[`Classifier`](src/main/java/com/secondbrain/classify/Classifier.java) готов к подмене реализации.

## Архитектура

```
[Вход: консоль · REST API · Telegram-бот (этап 5)]
              ↓
        [Java-бэкенд]
              ↓
 [Классификатор: правила → Anthropic API (этап 4)]
              ↓
    [SQLite]  →  [Notion API]
```

Несущих интерфейса два: `Classifier` и `NoteRepository`. За ними реализации меняются, не
задевая остального — именно так JSON-хранилище стало SQLite посреди проекта, причём
приложение работало после каждого шага.

```
src/main/java/com/secondbrain/
├── App.java                     точка входа: REPL / --stdin / --sync / --import-json / --serve
├── SecondBrainApplication.java  точка входа Spring (только режим сервера)
├── model/       Note, NoteType
├── classify/    Classifier, RuleBasedClassifier, Tags, Urls
├── storage/     NoteRepository, JsonNoteRepository, SqliteNoteRepository,
│                Storages, Timestamps, JsonToSqliteImporter
├── notion/      NotionClient, HttpNotionClient, NotionSyncService,
│                SyncLock, SqliteSyncLock, NotionFlushJob
├── core/        CaptureService  оркестрация: классифицировать → теги → сохранить → отправить
├── cli/         ConsoleApp
├── config/      AppConfig, OpenApiConfig
└── web/         NoteController, SyncController, ApiExceptionHandler, dto/
```

**Spring живёт на границах, а не в сердце.** В `CaptureService`, `NotionSyncService`,
`Storages` и во всём пакете `classify` нет ни одной аннотации фреймворка. Связка описана
один раз, в `config/AppConfig`. Поэтому консольный режим собирает те же детали вручную
и работает без Spring вовсе — захват мысли не зависит от запущенного сервера.

## Принятые решения

Короткие пояснения к выборам, о которых стоит спросить.

**`JdbcClient` вместо JPA/Hibernate.** Решающим доводом была не «меньше магии», а переносимость
репозитория: `JdbcClient.create(dataSource)` работает **без** контекста Spring, поэтому один
класс обслуживает и сервер, и консоль. `EntityManagerFactory` вне контейнера не поднять.
Две второстепенные причины: диалект SQLite у Hibernate — community-уровня, вне тестируемой
матрицы, а артефакта `flyway-database-sqlite` на Maven Central не существует вовсе.
Адаптер на JPA поверх PostgreSQL запланирован отдельным этапом — он сможет пройти тот же
`NoteRepositoryContractTest`.

**Теги JSON-колонкой, а не таблицей `note_tags`.** Так `save()` остаётся одним INSERT и
атомарен сам по себе. Отдельная таблица потребовала бы транзакции, а в консольном режиме
контекста Spring нет — `@Transactional` там молча не сработал бы. SQLite умеет искать
и внутри колонки: `SELECT n.* FROM notes n, json_each(n.tags) t WHERE t.value = ?`.

**Время текстом постоянной ширины.** В SQLite нет типа «дата», сортировка строковая,
а `Instant.toString()` обрезает незначащие нули — и `…06Z` оказывается *позже* `…06.3Z`
(`'Z'` 0x5A > `'.'` 0x2E), то есть лента молча перемешалась бы. См.
[`Timestamps`](src/main/java/com/secondbrain/storage/Timestamps.java).

**Синхронная отправка в Notion внутри запроса.** `POST /notes` ждёт ответа Notion, поэтому
зависший Notion означает медленный запрос. Принято осознанно: зато ответ честно сообщает
`SENT` или `QUEUED`, а инвариант «ноль потерь» виден в трёх строках `CaptureService`.
Асинхронность добавила бы третье состояние и много механики ради однопользовательского
инструмента.

**Миграция хранилища через переключатель.** Реализации JSON и SQLite сосуществуют, выбор —
`SECOND_BRAIN_STORAGE=json|sqlite`. Откат стоит одной переменной окружения, а не
восстановления из копии, и обе реализации держатся одного
[контрактного теста](src/test/java/com/secondbrain/storage/NoteRepositoryContractTest.java).

## Настройка Notion

Без настройки приложение работает — просто хранит заметки локально. Чтобы они улетали в Notion:

1. **Создай интеграцию** на [notion.so/my-integrations](https://www.notion.so/my-integrations)
   → *New integration* → скопируй **Internal Integration Secret**.
2. **Создай 4 базы** (идеи / задачи / ссылки / заметки) со свойствами:
   `Мысль` (title), `Захвачено` (date), `Теги` (multi-select), `Источник` (select),
   `ID` (text); у базы ссылок дополнительно `Ссылка` (url).
3. **Дай интеграции доступ**: на странице с базами → `···` → *Connections* → выбери интеграцию.
4. **Заполни настройки**:

```bash
cp notion.properties.example notion.properties
# впиши токен и id баз (id — часть URL базы)
```

Токен можно задать и переменной окружения `NOTION_TOKEN` — она имеет приоритет.
Файл `notion.properties` не коммитится.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SECOND_BRAIN_STORAGE` | `sqlite` | Хранилище: `sqlite` или `json` |
| `SECOND_BRAIN_DB` | `data/second-brain.db` | Файл базы SQLite |
| `SECOND_BRAIN_DATA` | `data/notes.json` | Файл JSON (прежнее хранилище, источник импорта) |
| `NOTION_TOKEN` | — | Секрет интеграции Notion; имеет приоритет над файлом |
| `NOTION_CONFIG_FILE` | `notion.properties` | Откуда читать настройки Notion |

Настройки сервера — в `src/main/resources/application.properties`
(порт, адрес, интервал фоновой досылки).

Перенос существующего файла JSON в SQLite:

```bash
java -jar target/second-brain.jar --import-json
```

Импорт идемпотентен и не изменяет исходный файл. Он откажется сообщить об успехе, если хоть
одна заметка потеряет отметку «уже в Notion» — эта отметка единственное, что отделяет
повторный импорт от дубликатов страниц.

## Тесты

```bash
./mvnw test
```

139 тестов. Кроме очевидного, они закрепляют решения, которые легко сломать незаметно:

- точность классификации не падает ниже 80% на фиксированном наборе реальных мыслей
- обе реализации хранилища удовлетворяют одному контракту
- строковый порядок времени совпадает с хронологическим
- захват удаётся при недоступном Notion, а заметка остаётся в очереди
- повторный импорт JSON→SQLite не воскрешает уже отправленную заметку
- два процесса, досылающих одновременно, создают ровно одну страницу в Notion
- тесты не могут добраться до настоящего Notion и до рабочей базы
  ([`NotionConfigSafetyTest`](src/test/java/com/secondbrain/notion/NotionConfigSafetyTest.java))

## Известные ограничения

- **Нет аутентификации.** Сервер слушает только `127.0.0.1`. Авторизацию придётся решить
  до того, как Telegram-бот (этап 5) начнёт обращаться к нему снаружи.
- **Остаётся узкое окно для дубликата.** Если страница в Notion создана, а записать её id
  локально не удалось, результат сообщается как `ORPHANED`, досылка останавливается, а id
  печатается, чтобы его можно было проставить вручную. Закрыть это полностью — значит читать
  страницу обратно по свойству `ID`, которое уже есть у каждой; вне объёма этапа 3.
- **У отката на JSON есть горизонт.** Заметки, захваченные после перехода на SQLite, в файле
  JSON не появятся — обратного переноса нет.
- **Держи `data/` вне OneDrive и сетевых дисков** — там блокировки SQLite ненадёжны.
